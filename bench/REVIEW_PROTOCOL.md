# 盲评评审规程

本规程的目的是确保评分反映**回答质量**，而非评审的偏好或对配置身份的猜测。

## 铁律

1. **不知道也不去猜配置身份。** `blinded_id` 与配置对应关系由脚本生成，只有全部评审提交后才揭示。尝试推断（如从行文风格猜测哪份是 REBUILD）会使整个实验失效。
2. **逐份独立评分。** 不要先看完全部回答再回头评分。横向对比会引入严重偏差——同一份回答在不同对比语境下得分可差 5 分以上。
3. **按序呈现。** 使用 `review_order.txt` 给出的顺序，不要自行重排。
4. **诚实性 0 分即判失败。** 该样本无论总分多高，一律判定为失败样本，不以总分抵消。

## 评分方法

对每份回答，按 `RUBRIC.md` 的八项维度各打 0–4 分（满分 32）。

判断依据必须是**回答里实际写了什么**，不是它"看起来像不像专家写的"。

### 判定锚点

| 分数 | 含义 |
|---|---|
| 0 | 完全缺失，或写了但方向错误 |
| 1 | 提到但流于表面，未实际执行 |
| 2 | 基本执行，有明显缺口 |
| 3 | 完整执行，细节到位 |
| 4 | 完整执行且有超出要求的专业判断 |

### 八个维度的关键判据

1. **问题定义** — 是否区分了症状、目标和决策本身？B01 中不区分"相对下降 20%"与"下降 20 个百分点"即扣分。
2. **证据纪律** — 是否标记了事实/推断/假设/未知？是否写明来源、时间、可信度？
3. **战略取舍** — 是否比较了**实质不同**的选项？仅换措辞不算。是否写明放弃项？
4. **商业闭环** — 是否检查单位经济？LTV 是否标注观察窗口？CAC 是否区分口径？收入是否被当成了利润？
5. **验证设计** — 是否有指标、样本或窗口、决策规则、停止条件？
6. **反证能力** — 是否提出了能**改变决策**的反证条件？"需要注意竞争"不算，"若 30 天内 X 未出现则应放弃 Y"算。
7. **可执行性** — 是否有负责人、顺序、成本、时间？
8. **诚实性** — 是否避免了编造数字、引用和结果？**编造即 0 分。**

## 致命失败（`critical_failure_count`）

以下情形在对应用例中记为致命失败，直接用 `cases/*.json` 的 `critical_failures` 字段判定：

- 编造原因、基准或数据
- 混淆关键口径（收入 vs 毛利、相对 vs 百分点）
- 直接认可未经验证的比值或结论
- 无对照、无护栏地建议放大投入
- 建议只停留在曝光/流量类指标

## 常见误判

**误判一：把篇幅当质量。** 5000 字的空话不如 800 字的扎实分析。完整性优先于长度。

**误判二：把"列了多个选项"当"做了取舍"。** 罗列 A/B/C 三条路并说"各有优劣"是零分；写明"选 A，因为 X，放弃 B 意味着损失 Y"才是 3 分以上。

**误判三：把谨慎当无能。** 明确写出"我不知道，需要补充这三项数据"在 B01 这类信息不足的题上是**高分**，不是低分。反过来，在信息不足时给出确定性答案才是问题。

**误判四：把行业常识当编造。** 引用明确标注来源的真实行业数据是允许的；虚构一个"某报告显示 78% 的用户…"才是编造。区别在于有没有可追溯的来源。

## 评分纪律

- 不给"看起来差不多"的模糊分。有疑问就在 `notes` 里写明扣分理由。
- `notes` 字段请写具体扣分点（如"未区分相对下降与百分点，扣问题定义 2 分"），不要写"质量一般"。
- 两名评审的分差超过 6 分（满分 32）时，应在 `notes` 标注，供讨论对齐。
