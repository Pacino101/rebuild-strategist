# legacy/v3.1 — 已废弃的 V3.1 版本存档

**这不是主分支。** 主分支是 `main`，当前版本从 V3.2.0 起。

这个分支的存在只有一个目的：**保存版本历史**。

> 主仓库 README 的「原创性边界」一节写着：
> 原创性应以**具体实现、独立文档、版本历史和可复现实验**来建立。
> 把被取代的版本直接删掉，等于亲手毁掉其中一项证据。

## 分支内容

| 目录 | 说明 |
|---|---|
| `v3.1-original-package/` | V3.1 原始包。13 个专家角色 + 10 个第三方集成文档 + 工具注册表。 |
| `v3.1-dsh-package/` | V3.1 的 DeepSeek Harness 重打包版。角色契约经过改写以适应宿主，内容与上者**不完全相同**。 |

两份**都不是** `main` 的祖先，是独立内容。

## V3.1 与当前版本的关键差异

| | V3.1（本分支） | V3.2 及之后（`main`） |
|---|---|---|
| 定位 | 营销工具集成层 | 以决策为中心的方法论操作系统 |
| 角色 | 13 个专家（含 SEO/GEO、创意内容、CRM、媒介等） | 8 个职能角色，每个有独立使命、输入边界、追问清单与失败模式 |
| 第三方依赖 | n8n · PostHog · Mautic · Matomo · airbyte · postiz · twenty · openseo 等 10 项集成 | **全部移除**。数据接入改由使用者自建（本地文件或自己的 HTTP 端点） |
| 证据机制 | 通用模板 | 证据账本 + 分级 + 来源可核验 + 断链检测 |
| 状态管理 | 无 | 确定性状态机 + 阶段门禁 |
| 决策闭环 | 无 | 决策入库、复审提醒、结果回填与偏差归因 |
| 运行时 | 提示词 + 工具注册表 | 顺序编排器（角色调度 / 门禁判定 / 状态裁决） |

**为什么移除集成**：V3.1 的定位是「聚合一批第三方营销工具」，那条路线无法建立原创性，
也会把项目变成安装说明的集合。V3.2 选择了一条更窄但可验证的路——只管决策质量，
不碰执行工具。这是一个**方向性取舍**，不是能力退化，但确实失去了渠道执行相关的角色。

## 状态

**不再维护。** 不接受 issue、不接受 PR、不会有安全更新。

其中的集成文档引用了第三方项目，那些项目的现状本分支不做任何保证。

如果你需要 V3.1 的某个角色契约（例如 SEO/GEO 或创意内容），
正确的做法是**按 `main` 上的角色契约格式重写**——即包含独立使命、输入边界与越权拒绝规则、
专属追问清单、专属失败模式——而不是把旧文件直接搬回去。旧版角色正是 `main` 的
V3.2.0 变更记录里指出要修复的问题：13 个角色共用同一份通用模板。
